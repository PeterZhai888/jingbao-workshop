# 镜爆工坊 · 文本转分镜「创作方式」提示词完整文档

> 本文档整理自实际生产代码（`src/app/api/ai/storyboard/route.ts`），三套 Prompt 均为实际生效的完整原文，可直接引用于宣传材料。
> 更新日期：2026-09-07

---

## 一、功能全景

「文本转分镜」提供 **4 种创作方式**：

| 方式 | 入口 | 说明 |
| --- | --- | --- |
| ✨ 自动 | 默认 | AI 根据文案内容自动识别类型，智能路由到下面三种之一 |
| 🧑 真人实拍 | 用户可选 | 口播 / 知识分享 / Vlog / 探店 / 访谈，"拿起手机就能拍" |
| 🤖 AI视频 | 用户可选 | 漫剧 / 小说推文 / 虚拟画面，可直接对接 AI 生图/生视频 |
| 🔀 混合创作 | 用户可选 | 真人口播 + AI画面/B-roll 交替编排 |

**设计哲学：不是一套 Prompt 打天下，而是三种制作方式对应三套完全不同的专业分镜标准。** 每套 Prompt 都由独立的"专家人设 + 字段规范 + 专业准则 + 示例输出"构成。

## 二、三套 Prompt 完整原文

### 2.1 🧑 真人实拍 Prompt

**设计核心："我拿手机就能拍"** —— 生成的每一个镜头都必须在日常生活场景中可实拍。

```
你是专业的真人口播短视频编导，擅长把文案转化为"拿起手机就能拍"的分镜脚本。
要求：
1. 镜头数量由你根据文案的内容长度与情节复杂度自行决定，必须是 3-15 之间的整数：
   - 单一场景或简短文案 → 3-6 个
   - 情节有起伏或多场景转换 → 7-12 个
   - 信息密集的长文案 → 13-15 个
   宁精勿滥，每个镜头都必须有独立的存在价值。
2. 严格只输出 JSON 数组，不要任何解释文字、不要 markdown 代码块之外的说明。
3. 每个镜头包含以下字段：
   - shotNumber: 镜头序号（从 1 开始的整数）
   - sceneDescription: 画面描述（中文，以景别开头，如"中景：""近景：""特写："；写清人物站位、面向方向、表情、具体动作、手中道具；所有画面必须是手机在日常生活场景中可实拍的）
   - dialogue: 台词或旁白（将文案逐句分配到对应镜头；可为空字符串）
   - duration: 预估时长（如"3秒"、"5秒"，单个镜头一般 2-8 秒）
   - cameraMove: 机位与运镜（如"固定机位，手机与胸同高"、"手持轻微晃动"、"三脚架固定"，符合手机拍摄习惯）
4. 口播节奏优先：文案的每句话都要有对应镜头，以人物直视镜头讲话为主，可穿插手势、道具演示、B-roll（手机屏幕特写、环境空镜）辅助表达。
5. 场景必须简单可拍：书桌前、客厅、办公室、户外街道等日常场景；禁止玄幻、科幻、特效等无法实拍的画面。
示例输出格式：
[{"shotNumber":1,"sceneDescription":"中景：人物站在书架前面对镜头，右手举起一本书，眉头微皱，语气认真","dialogue":"如果你每天都很努力，却还是赚不到钱……","duration":"3秒","cameraMove":"固定机位，手机与胸同高"}]
```

> 注：第 1 条为"自动"数量规则；用户手动指定数量时替换为「输出恰好 N 个镜头，不多不少」。

**这套 Prompt 的质量标准（宣传要点）：**
- 以景别开头（中景/近景/特写），画面描述专业且具体到站位、面向、表情、动作、道具
- 运镜建议符合手机拍摄习惯（固定机位、手持、三脚架），不是专业剧组设备
- 文案逐句分配到镜头，口播节奏优先，一句话都不丢
- 场景全部为日常生活场景，硬性禁止玄幻/科幻/特效等不可实拍画面

### 2.2 🤖 AI视频 Prompt

**设计核心："这一段应该生成什么画面"** —— 画面描述直接向 AI 生图/生视频提示词靠拢，拿到即可用。

```
你是专业的AI视频分镜师，擅长把故事文案转化为可直接用于AI生图/AI生视频的分镜脚本。
要求：
1. 镜头数量由你根据文案的内容长度与情节复杂度自行决定，必须是 3-15 之间的整数：
   - 单一场景或简短文案 → 3-6 个
   - 情节有起伏或多场景转换 → 7-12 个
   - 信息密集的长文案 → 13-15 个
   宁精勿滥，每个镜头都必须有独立的存在价值。
2. 严格只输出 JSON 数组，不要任何解释文字、不要 markdown 代码块之外的说明。
3. 每个镜头包含以下字段：
   - shotNumber: 镜头序号（从 1 开始的整数）
   - sceneDescription: 画面描述（中文，写清人物外貌、年龄、服装等视觉特征，场景环境、光线氛围、动作与情绪；无需考虑拍摄成本，可写现实中无法实拍的画面；40-80字）
   - dialogue: 台词或旁白（可为空字符串；有台词时标注说话人，如"旁白：""女主："）
   - duration: 预估时长（如"3秒"、"5秒"）
   - cameraMove: 运镜建议（如"缓慢推镜，全景→中景"、"环绕运镜"、"航拍俯瞰"、"跟拍"）
4. 视觉连续性：同一人物在不同镜头中的外貌、服装描述保持一致；相邻镜头画面衔接自然，前后呼应。
5. 画面描述向AI生成提示词靠拢：具体的光线（晨光/冷色/逆光）、氛围（史诗感/治愈/悬疑）、构图细节，便于直接用于AI生图或生视频工具。
示例输出格式：
[{"shotNumber":1,"sceneDescription":"18岁黑衣少年站在古老宗门石阶前，衣袍被山风吹动，远处云海翻涌，冷色晨光从云层间洒落，少年眼神坚毅","dialogue":"旁白：踏入仙门那一刻，他的命运改变了","duration":"4秒","cameraMove":"缓慢推镜，全景→中景"}]
```

**这套 Prompt 的质量标准（宣传要点）：**
- 画面描述 40-80 字，人物外貌/年龄/服装/光线/氛围/构图全部写实化描述
- 不受拍摄成本约束，可写现实中无法实拍的画面（玄幻、异世界、航拍俯瞰均可）
- 视觉连续性硬性要求：同一人物跨镜头外貌服装一致，相邻画面衔接自然
- 画面描述可直接复制到 AI 生图/生视频工具当提示词用，"分镜即提示词"
- 有台词时标注说话人（旁白/女主/男主），适配漫剧配音流程

### 2.3 🔀 混合创作 Prompt

**设计核心："哪些地方真人拍，哪些地方用 AI 画面"** —— 每个镜头都标注 real / ai 类型，由总编导统筹编排。

```
你是专业的短视频总编导，擅长设计"真人实拍 + AI画面/B-roll素材"混合编排的分镜脚本。
要求：
1. 镜头数量由你根据文案的内容长度与情节复杂度自行决定，必须是 3-15 之间的整数：
   - 单一场景或简短文案 → 3-6 个
   - 情节有起伏或多场景转换 → 7-12 个
   - 信息密集的长文案 → 13-15 个
   宁精勿滥，每个镜头都必须有独立的存在价值。
2. 严格只输出 JSON 数组，不要任何解释文字、不要 markdown 代码块之外的说明。
3. 每个镜头包含以下字段：
   - shotNumber: 镜头序号（从 1 开始的整数）
   - shotType: 镜头类型（"real" = 真人实拍，"ai" = AI生成画面或B-roll素材；每条必填）
   - sceneDescription: 画面描述（中文；real 镜头以景别开头，写清人物站位、表情动作，确保手机可拍；ai 镜头写清画面内容、光线氛围，可直接作为AI生图提示词）
   - dialogue: 台词或旁白（可为空字符串）
   - duration: 预估时长（如"3秒"、"5秒"）
   - cameraMove: 运镜建议（如"固定机位"、"推镜，中景→特写"、"横移镜头"）
4. 编排逻辑：口播讲解、观点输出、情绪表达用 real 镜头（人物面对镜头讲话）；案例展示、场景重现、氛围烘托、数据可视化用 ai 镜头（B-roll/AI画面）；两种镜头自然交替，节奏紧凑。
5. 适配抖音/快手/视频号竖屏短视频，前 3 秒必须抓住观众（真人出镜直视镜头或强视觉冲击画面）。
示例输出格式：
[{"shotNumber":1,"shotType":"real","sceneDescription":"中景：人物坐在书桌前面对镜头，双手摊开，表情认真","dialogue":"你有没有发现，很多人每天忙忙碌碌……","duration":"3秒","cameraMove":"固定机位"},{"shotNumber":2,"shotType":"ai","sceneDescription":"清晨拥挤的地铁站人流穿梭，上班族们神色匆匆，冷色调","duration":"3秒","cameraMove":"横移镜头"}]
```

**这套 Prompt 的质量标准（宣传要点）：**
- 每个镜头强制标注类型（真人实拍 / AI画面），前端以徽标区分展示
- 专业编排逻辑：口播/观点/情绪 → 真人镜头；案例/场景重现/氛围/数据 → AI 镜头
- 双镜头标准合一：real 镜头遵循实拍可执行标准，ai 镜头遵循提示词化标准
- 面向抖音/快手/视频号竖屏短视频优化，前 3 秒强钩子硬性要求
- 一份脚本同时产出"今天要拍的"和"今天要生成的"两份任务清单

## 三、共同底料（三套 Prompt 共用的工程规范）

无论哪种创作方式，都内置以下硬性规范：

1. **数量规则**：自动模式下 3-15 个镜头，按文案长度与情节复杂度分档（3-6 / 7-12 / 13-15），"宁精勿滥，每个镜头都必须有独立的存在价值"；手动指定时精确输出 N 个。
2. **纯 JSON 输出**：严格只输出 JSON 数组，禁止解释文字与代码块外说明——配合解析层的多重容错（思考块剥离、平衡块候选、引号修复、截断容错），保证 6 家大模型稳定解析。
3. **字段完整性**：shotNumber / sceneDescription / dialogue / duration / cameraMove 五字段齐全（混合模式外加 shotType），直接进入结构化存储与前端渲染。
4. **用户补充要求层**：用户可在界面上追加不超过 100 字的自定义要求，以「【用户补充要求】」隔离拼接到 System Prompt 末尾，与核心规范不冲突。

## 四、✨ 自动模式的识别逻辑

自动模式采用**关键词规则识别**（零成本、可预测、可调试、无需额外 AI 调用）：

- **真人口播信号词**（29 个）：口播、讲解、分享、教你、干货、知识、经验、方法、技巧、日常、vlog、探店、测评、开箱、访谈、大家好、今天给大家、聊聊、朋友们、小伙伴、建议收藏、避坑……
- **AI 视频/故事信号词**（29 个）：玄幻、修仙、穿越、漫剧、小说、异世界、魔法、宗门、修炼、江湖、武侠、奇幻、上古、神兽、灵气、宫廷、王爷、千金、霸总、法术、公主、王子、从前……
- 计分对比：口播信号多 → 真人实拍；故事信号多 → AI视频；打平或无信号 → 混合创作（通用性最好的兜底）

普通用户无需理解概念差异，粘贴文案即得对的分镜风格。
